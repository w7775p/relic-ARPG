## 已经实现的功能

仓库基线已完成 M0～M2：3D 即时战斗、雷霆旋风、随机装备、拾取换装、背包仓库、出售、成长、整备及完整探险存档。用户已试玩 M2 并反馈效果可以；历史自动化记录为 92 项回归及 Windows 导出/启动通过。

SkillRunner 已运行普攻、旋风和能量；InventoryState.build() 从装备汇总 BuildDefinition。当前没有技能装配界面和独立被动选择。

上述后续阶段功能须在开工时核实。本卡的“前置完成后”描述属于依赖条件，不能直接当作当前已完成事实。

## 本次要做的任务

① 建立技能定义与装配状态：稳定技能 ID、中文名、标签、槽位适用规则、消耗和冷却说明。先接通已有普攻与旋风，保留现有攻击来源与触发行为。

② 采用三个主动槽的最小方案：左键基础攻击槽、右键主要技能槽、F 辅助槽。当前辅助槽为空；可选技能随后续任务加入。闪避、药剂单独处理，输入统一经过语义动作。

③ 制作六个真实生效的被动节点，覆盖伤害、暴击、范围、生命、护甲、回能；同时选择上限为三个。节点全部开放，在据点免费选择与重置；技能装配同样在据点调整。

④ 在现有整备界面加入装配入口、当前选择与中文属性变化。装备和被动共同重算；取消被动恢复原值，调整上限时钳制当前生命/能量，切换不能获得免费补满或重置冷却。

## 存档与兼容

从 main 当前版本号递增建立 D1 存档版本，提供 M2 v2 → 新版迁移。旧角色默认普攻＋旋风、辅助槽空、被动未选；物品、经验、难度、随机状态和在途战斗保持。新增装配与被动字段必须同时更新 SaveManager、SaveValidator、SessionSnapshot 和恢复入口；现有校验器会限制字段数量，禁止只向 JSON 塞字段。

## 验收标准

① 从主菜单新建角色，在据点选择三个被动并出发；用人工可算样例核对属性，取消后回到原值。第四个选择被正确拒绝，UI 显示原因。

② 旧版 M2 据点存档和战斗中存档均可继续；保存重启后装配一致，旧词条、生命、能量和冷却保持。

③ 普攻、旋风、暴击闪电和感电爆炸继续工作；新测试接入 tools/verify.py，原 M0/M1/M2 回归仍有对应覆盖。

功能验证通过 `python tools/verify.py --godot <引擎路径>` 执行；新增用例需要实际运行到完成标记。涉及显示、声音和操作的标准按可见运行与试玩记录验收，历史结果不能代替本次验证。
