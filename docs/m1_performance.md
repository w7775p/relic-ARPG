# M1 初次 100 怪压力测试

日期：2026-09-09。Godot 4.7.2，Linux 云端 CPU 为 AMD EPYC 9V74，运行环境可见 9 个逻辑处理器，系统报告内存约 15.6 GiB，容器内存上限 14 GiB。使用无窗口驱动、逻辑视口 1280×720、60 帧上限；没有 GPU 渲染与实机输入。

固定场地、种子 1701、自动巡场、雷霆旋风、持续目标 100 怪；前 5 秒预热后采集。脚本使用高生命角色，避免死亡中断性能测量。每帧最多补 8 名敌人，大规模爆炸后需要数帧补足，因此“目标 100”不代表每个采样瞬间恰好 100 名存活目标。

| 指标 | 初版敌人互相碰撞 | 原生局部避让 |
| --- | ---: | ---: |
| 持续时间 | 180 秒 | 180 秒 |
| 采样帧数 | 10,498 | 10,501 |
| 帧间隔 P50 | 16.652 ms | 16.651 ms |
| 帧间隔 P95 | 18.418 ms | 17.637 ms |

| 最长帧间隔 | 60.382 ms | 44.609 ms |

| 采样最低存活数 | 62 | 61 |

本次改动将敌人的物理碰撞掩码从 7 调整为 3，保留世界与玩家碰撞，敌人间采用 NavigationAgent3D 的局部避让，每名代理最多六个近邻。物理时间 P95 在本次环境下降约 63%。导航路径每物理帧推进，目的地每 0.4 秒错峰刷新。

两次运行均完成全程且无引擎错误。正式版本使用局部避让。限帧时的帧间隔包含等待时间，物理监控属于引擎的独立采样，两个指标不可相加。

**结论范围：**验证了当前规模下的 CPU、物理、节点更新与触发稳定性。当前没有地面掉落，未模拟未来 100 件物品；弹体由远程敌人实际产生，未固定为同时 30 枚。GPU、1080p 完整渲染、目标 Windows 电脑性能、内存峰值和 30 分钟循环仍待后续测量。当前结果不能用于最低配置承诺。

原始结果：[初版](performance/m1_before.json)、[局部避让](performance/m1_thunder.json)。复现命令见 README。

## 两套预设的可测差异

同一巡场逻辑、场地、种子和 100 怪补充规则下，基础装备前 30 秒击杀 20 名，雷霆旋风前 30 秒击杀 534 名。雷霆预设同时改变伤害、范围、速度、触发和能量循环，这组数据用于确认成型构筑会显著改变清怪能力；后续 M2 仍需调整获取速度和数值曲线。基础预设原始结果见 [m1_basic.json](performance/m1_basic.json)。
